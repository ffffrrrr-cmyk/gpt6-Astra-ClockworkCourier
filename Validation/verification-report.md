# U2 验证报告

## 状态

项目实现包含完整的开始、探索、战斗、死亡重试、永久能力、最终送达和结算循环。Windows x64 构建与内部自动检查已实际执行，结果以相邻 JSON/TXT 报告为准。正常键鼠通关、手感、中文界面可读性、难度与美术评价为 **待用户实测**，不宣称采购验收通过。

## 实际执行

- 使用 Unity 6000.6.7f1、URP 17.6.0、Windows x64 Mono 生成场景、网格、材质、主角及各类敌人预制体，并构建实际播放器。
- 规则检查覆盖单次挥击去重、受伤保护、死亡幂等、冲刺冷却、空电量基础冲刺、资源上限、重复奖励防护、存档还原、损坏存档拒绝、场景引用、参数资源及六个安全出生点。
- 独立播放器检查覆盖主菜单初始状态、开始游戏、敌人生成、暂停时计时/角色/平台冻结、重试后能力与出生点恢复、敌人奖励一次性、守门体解锁、送达结算和实际磁盘存档恢复。
- 三张 PNG 是真实独立播放器的 `Camera.Render` 输出，不是宣传效果图。它们不含 IMGUI 菜单和 HUD，因此不用于证明完整界面已通过视觉审核。
- 自动运行通过专用参数直接调用状态接口完成检查，不模拟用户按键通关，不据此声称路线难度或操作体验通过。

## 环境与性能边界

实际运行环境由 Unity SystemInfo 采集：Windows 10 64 位、Intel Core i5-14400F、NVIDIA GeForce RTX 5060、Direct3D 12；详见 `runtime-environment.txt`。

后台隐藏窗口的屏幕渲染受抑制，曾出现空白屏幕截图与不代表图形性能的 Update 循环帧率。该结果已作废，空白截图不作为交付证据。`performance-sample.txt` 明确标记环境受限；1080p 稳定 60 FPS 的目标仍待可见窗口实际试玩验证。

## 已修复的问题

修正 Unity 6.6 对旧 InstanceID API 的禁用、阴影枚举歧义和 URP 软阴影设置方式。分离 MonoBehaviour 文件，保留可序列化场景引用。修正齿轮表面法线与背面朝向，降低背景反光，区分三个区域色调。捷径通过永久桥梁实际改变路线；菜单模态框阻止底层按钮响应；正常重新开始保留单独确认。

## 待测及待补齐

1. 按 `PLAYTEST.md` 正常键盘完成整条路线，验证是否存在难以察觉的卡点，并评价角色转向、平台跟随、格挡窗口和守门体难度。
2. 20—30 分钟为提示词的目标时长，当前没有人工计时通关依据，不能认定已经达到。
3. 可见窗口的主菜单、HUD、帮助、设置、结算，以及不同分辨率的中文字体与可读性尚待用户审核。
4. 背景采用程序化模块重复构造，三段以布局、机制和灯色区分；是否达到用户要求的最终精品美术标准仍待用户评价。
5. 已从 Codex 应用核验并记录本会话标识；套餐、后端快照与平台原始导出待账号持有人补充。跨批次题材清单和权利确认待采购流程完成。

未发现的问题不等于不存在。收到反馈后仅修改相关机制并复测受影响部分。
